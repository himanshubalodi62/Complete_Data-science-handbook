Access --->Migrate --->Optimize---> Secure & Manage

* Helps you to migrate on-premises VMware vms, Hyper-V vms, Physical servers, other virtualized machines and private/Public cloud instances to azure.

VMware Migration;

VMware Vms can be migrated using Azure Migrate server Migration with the following two options:
* Agentless Replication: Migrate Vms without needing to install anything on them.
* Agent based Replication : Install an agent on the VM for replication.

Agentless replication is easier to deploy in VMware, But currently has some limitations,
	* Simultaneous replication - Maximum of 300 vms migrated at a time.
	* Vm must have 60 or less disk
	* Vm operating system may need manual changes befor migration.
	* Issue with linux/EUFI boot, encrypted disk/Volumes, NFS volumes, and target storage.

Deployment steps

* Prepare VMware servers and vms for migration ( Required in agent base and agentless) --> Configure a number of setting on VMware servers and vms.

* Add the server migration tools ( Required in agent base and agentless) --> Add the Azure Migrate Server Migration tool in the Azure Migrate project.

* Deploy the Azure Migrate Application ( Required in agent base and not Required agentless) -->Set up a lightweight on a Vmware vm for vm discovery and assessment.

* Install the Mobillity service on Vms (NOt Required in agent base and Required agentless) --> Install the mobility service on each vm want replicate

* Deploy the Azure Migrate Server Migration Replication Appliacation (NOt Required in agent base and Required agentless)

* Replicate VMs enable Vm replication  (Required in agent base and agentless) --> Configure replication settings and select vms to replicate

* Run a test migration  (Required in agent base and agentless) --> Run a test migration to make sure everything working as expected.

* Run a full migration ( Required in agent base and agentless) --> Migrate the vms

Azure to Azure Site Recovery

* Replicate Azure Vms to any other Azure location
* No infrastructure to deploy
* Automatically deploys ASR Mobility Service extension to protected machines
* Replicates 
	* VMS
	* Virtual Networks
	* Availability Sets
	* Storage Accounts
	* Optionally - you can specify your own Vnets. Storage Accounts and Availability sets

* Replicates on HTTPS channel on 443
	*Generates Azure engress cost for outbound traffic from primary region.

__________________________Azure to Azure Architecture_____________________


                              Cache data
Source environment(East-us) {Vm --->          __data flow______         target region { storage account ---> vm}
                             storage account     ___fail over___>

   
1- Vm is registered with azure site recovery 
2- Data is continuously replicated to cache
3- Cache is replicated to the target storage account
4- During failover the virtual machine is added to the target environment.
